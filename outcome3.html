Search Algorithm

Search, as the name implies, is the process of AI exploring its search space—consisting of every possible path, solution, and state that it can evaluate—to reach its goal. Search often comes with five main components: initial state (your starting point), goal test (test if you are at your destination), action (describe the possible step you can take during the path), transition model (describe the result after you move), path cost (the total expense of actions you took to reach your goal). There are also some other important terms such as search problem, what you are trying to solve; search tree, every possible path AI explored; search strategy, the behavior of the algorithm; state space, all the possible states of the problem; and environment, how the path and state look. There are also three fundatemematal search algorithm, which are Breadth-First Search (BFS), Depth-First Search (DFS), and A* Search.

For easier demonstration, let's have a example of a train station. We have nine section of this train station, A-I, and our search problem is try to get to section H. Our state space is how the layout of the train station looks like, which is the image below. And for a even simpler approach of this demonstration, we will assume the cost of each path will be one minute.

Breath-First Search

Breadth-First Search (BFS) is a search algorithm often used to find the shortest path to a goal. The search strategy, or the way it works, is that it searches layer by layer, which means we explore all the sections at one level before moving on to the next, trying to find which route would be the shortest. Our initial state will be section A, and we begin by exploring the very first three sections that are connected to A, which are sections B, E, and F. The possible actions are to go to section B, E, or F, using the First In, First Out (first come, first served) idea. In this example, B will be explored first, then E, and then F. For BFS, we will perform a goal test after every action we take, which, in this case, none of the three stations is section H, so we continue exploring. Using that concept of FIFO, we will explore sections that are connected to B first, then E, and then F again. We explore section C, then I, neither is H, continue explore. Section D and G are next on the list, and neither is H, so we continue exploring and finally reach our destination, station H. So our shortest, which is also our only path for this example, will be A>B>C>D>H. This route represents one branch of our search tree, and this costs us four. However, if H is not only connected to D but also I, the path the algorithm would take would be A>E>I>H, which is shorter and costs us only three. BFS, as we already covered, is utilized to find the shortest path to reach our goal, however, it is not cheap nor it is memory friendly. For simplicity, our example assumes every connection costs the same. But, for most, if not all, situation won't cost the same, so BFS might took the shortest but most expensive route. It is also not memory efficient because the algorithm must remember every single train section it did and didn't explore, and if this train didn't have nine but a million sections, BFS will not be ideal to be used.

Depth-First Search

Depth-First Search, or DFS, is a search that is often used to save memory. The search strategy of this search is basically to explore one whole connection before moving on to the next. Our initial state is still A, our legal action still B, E and F. We will move to B first, but unlike BFS, we will continue to explore this branch. We explore C, then D, then H, and the search ends here because we already found H. However, if instead we have H connected to D, and we have it connected to F, this means it will explore the whole train station similar to BFS. But, unlike BFS, it won't "remember" the path it explored; instead, it will take a new route, which makes it very memory-friendly. Besides that point, DFS is pretty much a luck-based search as if we weren't lucky and got that hypothetical situation where H connected to I, the algorithm took just as long as BFS. Besides the point that it is useful when you want to save memory, it doesn't care about path cost or the shortest route. The algorithm just dives blindly straight into one path and hopes that it's the right one.

A*/A-Star Search

A* Search is a search that known where its goal is at the begining and is used to find the cheapest path to a goal. It uses costs and estimates to determine which station to explore first by using the formula, f(n) = g(n) + h(n), where g(n) means the current path cost, h(n) means the remaining cost to reach section H, and f(n) is the total estimated cost. A* will priotize section that have the lowest estimated cost. To do this formula, we would find the f(n) of every section. Let's start with A, which is our initial state, so they don't have any cost, and the remaining cost to reach H is 4 because we need to explore four more stations to reach H. The formula would look like this: g(0) + h(4) = 4. Now we would check A's neighbors, B, F, and E. The current cost for all three of them is 1, but the remaining cost differs. h(n) for B is 3, but for F and E it is 5 because the algorithm needs to backtrack back to A to go over B which add another extra exploration step. The final f(n) for B is, g(1) + h(3) = 4; F and E is, g(1) + h(5) = 6. As B have the cheapest f(n), A* will decide to explore B and ignore both station F and E. Now the algorithm will still find the f(n) of the neighbor station to B, which is C, despite C being its only connection, and f(n) of C is 4. Now we repeat this step again for C's neighbor, D, which had f(n) of 4, and G has 5 because the algorithm has to backtrack to C as G isn't connected to H. Repeat what we've been doing: the f(n) of H is g(4) + h(0), which is 4. Due to the simplicity of the example, A* can skipped the hassle of exploring E, F, and G, however, in real-life, the path cost rarely be 1. If in this situation that B turned out to be more expensive than F, the algorithm will explore F but ultimately resolve to explore B because H doesn't connect to F. A* often ultized for problem that require a lot of nodes, and often the goal would have mutiple connection with those nodes. They are also being utilized when the problem involves different costs because it potentially skips a lot of nodes and also finds the cheapest way to finish the search problem. However, one problem with it is that it is not memory efficient because it needs to know the current cost to use in its formula, which means it has to keep track of the cost of the previous path that it explored and also skipped paths in case it needs to backtrack here.

Adverserial Reasoning

Unlike Search, Adverserial Reasoning involved two or more agents. Adverserial Reasoning is basically the process of AI accounting the other agent's strategies and intent to make an action. There is some components coming along with it just like the Search Algorithm which are Game State, Initial State, Action, Game Tree, and Terminal State. The Game State tells you what is the current situation of the game, for example,

in this picture the Game State is the White Rook is checking the Black King. The Initial State is pretty much the same as Search Algorithm's Initial State, the starting point of the game. The Terminal State is simply where the game end, or with the Chess example, it is when one side got checkmate. Action is also similar to Search Algorithm's Action which is the possibble move that one player make. Finally, the Game Tree, which is simply just consist of all possible a player made and its result. Imagine if you were playing Rock, Paper, Scissor with your friend and you both have Rock so the game continue and there are three possible action which are Rock again or Paper or Scissor. If you played Rock again, and your friend too, you draw again. But if you choose Scissor and your friend decided Rock, you lost, but you won if you go with Paper and your friend go with Rock. That is basically the Game Tree: each Game State represents a node of the tree and each Action represent the Branch. And when talking about Adverserial Reasoning, there are two fundemental algorithm, which are Minimax and Alpha-Beta Pruning.

Minimax

Minimax is an algorithm where you, the maximizer, try to get the highest score while your friend, the minimizer, tries to get you the lowest score. Let's use this example of Tic-Tac-Toe game below

In this example, let's say you are O and your friend is X, and it's currently O's turn, which is you, the Maximizer. You have three legal moves: the middle of the first column, the middle of the top row, and the rightmost spot in the top row. If you decide to draw O in the middle of the first column, you have won the game, and it's a +1 for you. However, if you choose the rightmost spot in the top row, you allow your friend to have their X in the top middle and win the game, which is a -1 for you. Now if your friend decides not to do that and puts their X in the middle of the first column instead, you can only put your O in the top middle, and the game is now a tie, and you got 0 points. For your final legal move, which is middle top, you got a 0, and the game continues. Now your friend has two moves they can make: the middle of the first column or the rightmost of the top row. If they choose the second option, you win the game, +1 for you; otherwise, it would be a tie and 0 for you. That is basically how Minimax works; however, in a more complicated game such as Chess, Minimax might take forever because the algorithm accounts for every single move and its result.

Alpha-Beta Pruning

This is why we turn to Alpha-Beta Pruning. It is pretty similar to Minimax; Alpha is basically the maximizer and vice versa for Beta. However, the main difference between these two is that Minimax checks every single node and branch of the Game Tree, but Alpha-Beta Pruning will completely ignore branches that are not beneficial for you, hence the name "Pruning." Remember the score in Minimax we've talked about above; those are the core parts of how Pruning works. They use those scores to evaluate which branch to prune.

Let's say you and your friend play another little game, and that is your Game Tree. You are still the maximizer, or Alpha, and your friend is still the minimizer, or Beta. At the beginning of the game, neither of you knows what the possible scores are yet, so you both assume the worst-case scenario for both of you, where your worst case is Alpha = -∞ and your friend is Beta = +∞ , so we are going to have a point (α, β) be (-∞, +∞). Now, we would go to the very bottom of the Game Tree, where the scores are, and begin this algorithm. First, because A1 is your turn, your job is to compare the score to see whether or not it is higher than -∞ and obviously 3 is higher, so we replace the -∞ with 3, thus having (3, +∞). Next, we would check the other score, which is 5, and 5 is greater than 3, so we replace it again, and so the max score we can get from this branch is 5. Now this score would be sent back to the previous node, the A(MIN) node, which is your friend, and because they are the minimizer, they would see if 5 is less than +∞ , which it is, so the new point for them would be (-∞, 5). To the second branch, with that new "coordinate" point and because A2 is also the maximizer, and because 6 is greater than -∞, they replace the -∞ and we get the new point of (6,5). This is where the pruning happens. Whenever β is less than or equal to α, the algorithm would stop checking the other score branch regardless of how high or low the score is. In this situation, because your friend already knows that they are guaranteed a 5 on A1's branch, they wouldn't allow you to have a 6 or 9 anyway. Even if instead of 9 it's 0, you, the maximizer, wouldn't choose it either and go with 6; thus is why we prune the 9. Now, because 6 is greater than 5 and your friend wants you to have the lower score, they would give you the 5, and now this 5 will get sent back to the previous node of R(MAX), which means the highest score you can get right now is 5. After this, we move down the branch of B1 to repeat our very first step, and 2 is the highest, so we send this back to node B(MIN). Because 2 is less than +∞, they would replace +∞ with 2, and also because B(MIN) "inherits" the point (5, +∞) from R(MAX), the new point we got is (5, 2), which means the entire B2 branch is pruned. So now the best score you can get is 5, and thus we can conclude how Alpha-Beta Pruning works.
